# Configuration reference: Spend cube refresh retention

## Location
Admin > Spend Analytics > Settings > Spend cube refresh > Retention

## Purpose
Controls the retention applied when a spend cube refresh is created, updated or processed. Changes apply to new records only unless the administrator selects Reapply to open records.

## Allowed values
| Value | Guidance |
|---|---|
| Per business unit | Recommended for most tenants |
| Strict | Use for high-volume tenants |
| Global | Requires L2 enablement |
| 5 minutes | Legacy behaviour |

## Impact of changes
This article applies to tenants on release 26.1 and later. Earlier releases display the same behaviour but use a different admin menu path. If more than one tenant reports the same error within 24 hours, treat it as a potential platform incident and check the Known Issues list before troubleshooting individually. The issue affects only the tenant where the configuration was changed. Other tenants on the same release are not affected. An incorrect value here is a common contributor to E-6159 and E-6213.

## Audit
Every change to this setting is recorded in the admin audit log with the acting administrator's role and a timestamp.
