# Configuration reference: Spend cube refresh numbering

## Location
Admin > Spend Analytics > Settings > Spend cube refresh > Numbering

## Purpose
Controls the numbering applied when a spend cube refresh is created, updated or processed. Changes apply to new records only unless the administrator selects Reapply to open records.

## Allowed values
| Value | Guidance |
|---|---|
| 30 days | Requires L2 enablement |
| Off | Recommended for most tenants |
| 15 minutes | Legacy behaviour |
| 60 minutes | Legacy behaviour |

## Impact of changes
If more than one tenant reports the same error within 24 hours, treat it as a potential platform incident and check the Known Issues list before troubleshooting individually. Collect the tenant ID, the affected record ID, the exact error text and the time of failure in UTC before escalating. The issue affects only the tenant where the configuration was changed. Other tenants on the same release are not affected. An incorrect value here is a common contributor to E-6213 and E-6285.

## Audit
Every change to this setting is recorded in the admin audit log with the acting administrator's role and a timestamp.
