# Configuration reference: Data load timeout

## Location
Admin > Spend Analytics > Settings > Data load > Timeout

## Purpose
Controls the timeout applied when a data load is created, updated or processed. Changes apply to new records only unless the administrator selects Reapply to open records.

## Allowed values
| Value | Guidance |
|---|---|
| 15 minutes | Use for high-volume tenants |
| Strict | Requires L2 enablement |
| Off | Legacy behaviour |
| On | Requires L2 enablement |

## Impact of changes
If more than one tenant reports the same error within 24 hours, treat it as a potential platform incident and check the Known Issues list before troubleshooting individually. This article applies to tenants on release 26.1 and later. Earlier releases display the same behaviour but use a different admin menu path. Customers typically report this when a data load is processed in bulk or immediately after an administrator changes Spend Analytics settings. An incorrect value here is a common contributor to E-6213 and E-6182.

## Audit
Every change to this setting is recorded in the admin audit log with the acting administrator's role and a timestamp.
