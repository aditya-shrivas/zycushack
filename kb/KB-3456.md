# Configuration reference: Session routing

## Location
Admin > Platform > Settings > Session > Routing

## Purpose
Controls the routing applied when a session is created, updated or processed. Changes apply to new records only unless the administrator selects Reapply to open records.

## Allowed values
| Value | Guidance |
|---|---|
| On | Requires L2 enablement |
| Global | Use for high-volume tenants |
| Strict | Legacy behaviour |
| Lenient | Recommended for most tenants |

## Impact of changes
If more than one tenant reports the same error within 24 hours, treat it as a potential platform incident and check the Known Issues list before troubleshooting individually. Collect the tenant ID, the affected record ID, the exact error text and the time of failure in UTC before escalating. Customers typically report this when a session is processed in bulk or immediately after an administrator changes Platform settings. An incorrect value here is a common contributor to E-8175 and E-8225.

## Audit
Every change to this setting is recorded in the admin audit log with the acting administrator's role and a timestamp.
